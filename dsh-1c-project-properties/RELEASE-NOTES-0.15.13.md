# 0.15.13

## Серверы MCP: панель менеджера снова их видит

Сборка на ядре `0.2.2-rc.3` объявляет службу `mcpManager` сама, и запись, сделанная
через её `register(name, entry)`, попадает в реестр ядра. Панель
`@wingsky-1/dsh-mcp-manager` строит список только из своего хранилища и своего
`runtimeRegistry`, поэтому серверы плагина — справка по API платформы
(`1c-platform-context`), проверки BSL (`1c-bsl-checks`) и 1С:Напарник
(`1c-naparnik`) — работали, но в панели отсутствовали: видно было три строки из
файла, и это читалось как «сервер не поднялся».

Теперь плагин регистрирует их через `registerServer`, когда менеджер его
предлагает (наша редакция менеджера дополняет ядровую службу этим методом), а
`register()` остаётся запасным путём для сборок без прежней линии API. Снятие идёт
парным `unregisterServer`, состояние — из `list()`.

Следствие, о котором стоит знать: инструменты этих серверов доступны модели через
промежуточные `ws_mcp_search` / `ws_mcp_detail` / `ws_mcp_call` / `ws_mcp_list`, а
не прямыми `mcp__<сервер>__<инструмент>` — так устроен реестр менеджера.
